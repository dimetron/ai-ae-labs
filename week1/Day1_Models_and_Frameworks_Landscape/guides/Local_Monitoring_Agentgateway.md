# Локальний моніторинг агентів: усі виклики через agentgateway

**Тиждень 1, частина 1 · Додатковий матеріал до ДЗ 1 · ~20 хвилин на встановлення**

> **Станом на 08/2026.** Стек перевірено проти **agentgateway v1.4.1** (конфіг: `demo/1_ai-gateway/config/agentgateway.yaml` (`demo/1_ai-gateway/config/agentgateway.yaml` у пакеті курсу)). Назви полів конфігу й теги образів звіряйте перед використанням — проєкт молодий і схема змінюється між мінорними релізами.

---

## Навіщо це на першому тижні

У ДЗ 1 ви будуєте `Cross-Model Benchmark Harness` — таблицю «модель × латентність × вартість». І тут виникає незручне питання, яке більшість туторіалів обходить:

**звідки ви знаєте, що ваш вимір правильний?**

Ваш харнес міряє те, що бачить *агент*: скільки минуло від виклику до відповіді й скільки токенів повернув провайдер у `usage`. Але між агентом і провайдером є мережа, ретраї, стрімінг і ваш власний код. Коли на рахунку в кінці місяця стоїть $2 800, а у вашій табличці — $40, сперечатися з рахунком ви будете без доказів.

**agentgateway** — це OpenAI-сумісний проксі, який стає між вашим агентом і моделлю. Агент думає, що говорить зі звичайним OpenAI endpoint; насправді кожен виклик проходить через гейтвей, який пише:

- **трасу** кожного запиту (Jaeger) — видно, де саме витрачено час;
- **метрики** (Prometheus → Grafana) — RPS, латентність, токени;
- **реалізовану вартість у USD** на кожному рядку access-log — не «за прайсом», а за фактичними токенами.

Це і є різниця між «вартість за прайс-листом» і **ефективною вартістю**, про яку йдеться в лекції. Гейтвей рахує друге.

> **Межа курсу — читайте уважно.** agentgateway у повному обсязі (policy, RBAC, MCP-gateway, A2A, Kubernetes) — це **поза межами цього курсу**. Тут ми свідомо беремо від нього **одну функцію: локальну спостережуваність**. Нічого з політик і деплою в цьому курсі не буде. Якщо вам зараз хочеться більше — це добрий знак, і поза межами курсу воно є.

## Чому це ще й ваш офлайн-шлях

Найважливіше для тих, у кого **немає жодного API-ключа**: у стеку є `mock-llm` — крихітний OpenAI-сумісний бекенд, який повертає заготовлену відповідь.

Це означає, що **всю ДЗ 1 можна пройти без жодного ключа й без жодної копійки витрат**. Цифри будуть несправжні (модель фейкова), але весь інженерний ланцюг — агент → гейтвей → бекенд → траса → метрика — справжній. Ключі додасте потім.

## Крок 1. Підняти стек (одна команда)

```bash
cd demo/1_ai-gateway
docker compose up -d
```

> **Немає Docker?** Достатньо самого бінарника гейтвея: завантажте `agctl` під вашу
> платформу зі [сторінки релізів agentgateway](https://github.com/agentgateway/agentgateway/releases)
> (станом на 09/2026 — v1.5.0; `agctl-darwin-arm64`, `agctl-linux-amd64` тощо),
> зробіть файл виконуваним і запустіть із конфігом `config/agentgateway.yaml`
> із цієї теки. У цьому режимі у вас буде сам гейтвей (порт `:4000`) без Jaeger,
> Prometheus і Grafana — траси дивитимете в access-log гейтвея. Для повного стеку
> з дашбордами потрібен Docker compose вище.

Піднімається шість сервісів:

| Сервіс | Порт | Навіщо |
|---|---|---|
| `agentgateway` | `:4000` | OpenAI-сумісний API — сюди дивиться ваш агент |
| `agentgateway` (admin) | `:15000` | адмін-UI гейтвея |
| `mock-llm` | `:8080` | фейковий бекенд, працює без ключів |
| `jaeger` | `:16686` | траси |
| `prometheus` | `:9090` | метрики |
| `grafana` | `:3000` | дашборди (анонімний вхід, роль Admin) |

Перевірка, що гейтвей живий — звичайний OpenAI-виклик:

```bash
curl -s http://localhost:4000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"mock-gpt","messages":[{"role":"user","content":"привіт"}]}' | head -20
```

Якщо повернувся JSON із `choices` — усе працює. Відкрийте <http://localhost:16686> (Jaeger) і знайдіть трасу цього запиту.

> **Якщо `docker compose up` не піднімається**, не воюйте з ним довго: моніторинг — **не** обов'язкова частина ДЗ (див. «Як це оцінюється»). Зробіть основне завдання напряму до провайдера й поверніться сюди пізніше.

## Крок 2. Направити агента через гейтвей

Ось уся інтеграція. У ADK Go v2 пакет `openaimodel` приймає `BaseURL` «for OpenAI-compatible endpoints» — рівно той самий механізм, яким лаба вже підключає локальну Ollama. Змінюється **лише адреса**:

```bash
export AGENTGATEWAY_BASE_URL=http://localhost:4000/v1
# ключ гейтвею локально не потрібен — у коді підставляється заглушка
```

У каталозі моделей (`solution/catalog.json`) для цього вже є рядок:

```json
{
  "id": "mock-gpt",
  "provider": "agentgateway",
  "label": "Mock через agentgateway (офлайн-шлях, без ключів)",
  "pricing": { "input_per_mtok": 0, "output_per_mtok": 0, "self_hosted": true }
}
```

Код, який це обробляє (`solution/agent.go`), — той самий `openaimodel`, що й для Ollama:

```go
case "agentgateway":
    key, _ := adkenv.Key("AGENTGATEWAY_API_KEY")
    if key == "" {
        key = "not-needed-for-local-agentgateway"
    }
    m, err := openaimodel.NewModel(ctx, spec.ID, &openaimodel.ClientConfig{
        APIKey:  key,
        BaseURL: value, // AGENTGATEWAY_BASE_URL
    })
```

**Це вся «інтеграція».** Жодного SDK гейтвея, жодної залежності в `go.mod`. Гейтвей — це просто інша адреса. Запам'ятайте цю властивість: усе, що виглядає як OpenAI endpoint, взаємозамінне, і це головна причина, чому OpenAI-сумісний формат став де-факто стандартом.

## Крок 3. Подивитися на два числа, які не збігаються

Запустіть бенчмарк і поруч відкрийте Grafana (<http://localhost:3000>).

Тепер у вас є **два незалежні виміри одного й того самого запиту**:

1. **Meter агента** (`BeforeModelCallback` / `AfterModelCallback` у `agent.go`) — те, що бачить агент;
2. **Access-log гейтвея** — `cost_total`, `cost_input`, `cost_output`, порахований із каталогу цін.

Порівняйте їх у README. Питання, на яке треба відповісти двома-трьома реченнями: **де вони розходяться і чому?** Підказки, що варто перевірити: чи рахує ваш Meter ретраї; чи включає він системний промпт; що відбувається зі стрімінгом.

> Це і є практичний сенс усього блоку про токенову економіку: **вартість вимірюють на межі системи, а не всередині агента.**

## Як це оцінюється

**Базові 80 балів зараховуються без цього кроку.** Цей матеріал **не входить** до обов'язкового шляху ДЗ 1: Docker — це прихований пререквізит, і робити його обов'язковим на першому тижні означало б втратити частину групи ще до першого працюючого агента.

Але якщо ви його пройшли — порівняння двох вимірів із Кроку 3 зараховується як пункт «Два виміри однієї вартості» в `++ Advanced` (**+20 додаткових балів** понад базові 80), і при цьому не потрібне для сертифіката.

## 🔥 Бонус-трек (для тих, кому мало)

1. **Failover, який видно.** У конфізі вже є віртуальна модель `resilient`: перший бекенд (`dead-backend`) завжди мертвий, і гейтвей провалюється на живий. Направте агента на `resilient`, знайдіть у Jaeger трасу, де видно обидві спроби, і поясніть у README, чому агент **не помітив** збою. Це перше знайомство з ідеєю, яку Тиждень 4 розгортає повністю: надійність — властивість системи, а не промпту.
2. **Guardrail, який спрацьовує.** У конфізі є правило, що **відхиляє** запит із credentials (`api_key=...`, `password=...`) зі статусом 400. Спробуйте надіслати такий промпт через гейтвей і подивіться, що повернеться. Зв'яжіть це з Кроком 0.2 ДЗ (хук проти витоку секретів): це та сама загроза, спіймана на іншій межі — одна на боці git, друга на боці мережі.
3. **Своя ціна.** Додайте до `config/catalog.json` гейтвея рядок для моделі, якою ви реально користуєтесь, із її актуальним прайсом, і звірте `cost_total` гейтвея з власним підрахунком у харнесі. Розбіжність більш ніж на 10% — привід розібратися, хто з вас двох помиляється.

Ця сама змінна `AGENTGATEWAY_BASE_URL` працює для **будь-якої лаби курсу**, де агент ходить в OpenAI-сумісний бекенд. Один раз піднявши стек, ви отримуєте наскрізну спостережуваність на всі шість тижнів: у Тижні 4 через неї добре видно ретраї tool-харнесу, у Тижні 6 — скільки насправді коштує self-improvement цикл.
